# 任务交接文档 Skill

## 概述

在项目根目录维护一份结构化的 `progress.md`，让用户可以在任意新对话中快速恢复任务上下文，最小化 token 占用。

**核心价值**：用户在新对话中只说一句"读取进度并初始化"，agent 就能自动 clone 仓库、启动预览服务、返回访问链接，完全无缝衔接。

---

## 文档模板（7 模块固定结构）

```
# [项目名] — 任务交接文档

> 最后更新：YYYY-MM-DD HH:MM:SS
> 维护约定：阶段性产出完成后更新；新对话开始时先读取本文档
> ⚠️ 本文档覆盖 N 条并行工作流，所有事项以 `[工作流]` 标签区分

---

## 1. 任务概览（必须按工作流分 A/B 区，每个区有独立的优先级表）

### A. [工作流名称]
- 当前目标
- 平台/模块矩阵（如适用）
- 当前优先级表

### B. [工作流名称]
- 当前目标（如适用）
- 当前优先级表

## 2. 进度状态
> 所有条目必须携带 `[工作流]` 标签。如有多层分类，格式为 `[工作流] [平台/模块]`。

- ✅ 已完成（底部按日期分组记录本会话完成，顶部可放摘要）
- 🔄 进行中
- ⏳ 待办
- ❌ 已废弃

## 3. 交付物清单
分三类：workspace 文件（目录树 + 注释）、tdrive 文档（名称/内容/状态）、本地参考文档（非交付物）
状态标记：✅ / 🔄 / ⏳ / ❌ / ⚠️

## 4. 关键决策（按工作流分两段，每段编号独立连续）
### A. [工作流名称]
4A.1 → 4A.2 → ...

### B. [工作流名称]
4B.1 → 4B.2 → ...

## 5. 核心上下文
路径、Token、预览机制、关键数据。只列事实，不确定的标注"待确认"。

## 6. 下一步行动
- 新对话启动指令（三步：clone → cat progress → supervisord + notify）
- 待用户决策（按工作流分列）
```

---

## 标签体系（铁律 10）

**所有进度条目必须携带工作流标签**，格式为 `[工作流] [平台/模块]`。

| 当前项目的工作流 | 标签 | 说明 |
|----------------|------|------|
| 产品设计 | `[产品设计]` | PRD、原型、需求、评审，面向业务方和研发 |
| 需求设计中心建设 | `[中心建设]` | OSS/ECS/Git/预览/域名/文档站点，PM 个人基础设施 |

平台子标签（可选，仅产品设计用）：`[启航]` `[知行]` `[聆听]` `[新一代首页]`

**示例**：
- `[产品设计] [启航] app_map 搜索结果悬停下界钳制`
- `[中心建设] OSS 防盗链 Referer 白名单`
- `[产品设计] [新一代首页] 待办工作台方案设计`

## 已完成列表压缩规则（B+C 模式）

当 §2 已完成条目数量膨胀到影响阅读时，agent 应**主动提示**用户：

> "已完成列表当前 X 条，是否压缩为按平台/阶段的摘要？"

**用户确认后执行压缩**：将指定时间范围之前的已完成条目，按工作流+平台归并为摘要段。例如：

```
### ✅ 2026-07 及之前（已归档）

**产品设计·启航**：PMS关联全链路、操作手册PRD+原型、更新日志PRD+原型、应用地图改版（Banner/分类/卡片/搜索/详情页）、管理端6页原型、导航组件化……共 N 项，均已评审或开发中

**产品设计·聆听**：状态增加/建议导出/统计大盘 PRD+原型完成，已录入设计中心

**中心建设**：OSS+ECS外网发布、GitHub仓库打通、预览服务、防盗链白名单、需求中心导航模块化
```

**压缩不可自动执行**，必须用户口头确认。压缩后原始条目可删除。

## 执行流程

### 1. 读取现状
- 读取已有 `progress.md`（如果存在）
- 列出当前项目文件结构
- 如有 tdrive，列出资产库文档
- 如有 git，查看最近 commit 和未推送提交

### 2. 对比变化
- 识别新增/删除/修改的文件
- 识别已完成的任务（从 🔄 变为 ✅）
- 识别新增的待办
- 识别已过期的决策和描述

### 3. 更新文档
- **先获取当前系统时间**：执行 `date "+%Y-%m-%d %H:%M:%S"`，用结果更新 `最后更新` 字段。禁止跳过这一步直接填日期或时间。
- 只更新有变化的模块
- 不重写全文
- 保持每个条目一句话，精炼

### 4. 内容修剪
- **删除已不是关键内容的条目**：如果用户明确表示某模块"不在原型中做了""不是关键内容"，从 progress.md 中移除
- **标记已废弃而非保留**：原型页面被替代/砍掉的，标记 `⚠️已弃用` 或 `~~删除线~~`
- **关键决策只保留当前有效的**：已推翻的方案不要留在 §4 里

### 5. 编号维护
- §4 编号格式为 `4A.1` / `4B.1`，各自连续
- 删除中间某一项后，后续编号逐项前移
- **绝不允许出现重复编号**

### 6. 提醒同步
- 完成后提醒用户：是否同步到 tdrive、是否需要推送 Git（遵循铁律 5）

---

## §6 新对话启动指令规范

### 必备三步

```
第一步（初始化仓库）：完整可执行的 git clone 命令，Token 已内嵌
第二步（读取进度）：cat /workspace/prototype/progress.md
第三步（启动预览，每次都做）：supervisord 托管 8080 + notify 获取链接
```

### Token 内嵌规范
- 用户希望 Token 直接写在 progress.md 中，避免每次额外发送
- **必须拆分 Token** 以规避 GitHub push protection
- 拆分方式：将 Token 从中间断开，用 bash 相邻引号自动拼接 `"前半段""后半段"`
- 同时在 clone 和 push 命令中使用拆分后的格式

### 链接交付规范
- agent 只需提供 `notify` 返回的链接，用户自行打开

---

## "读取进度并初始化"流程

1. 读取 progress.md
2. 定位到 §6 "新对话启动指令"
3. 依次执行第一步（clone）、第三步（启动预览）
4. 返回预览链接给用户
5. 汇报当前优先级和可执行任务

---

## 铁律

1. **只写已经确认过的事实**。不确定的标注"待确认"或留空。
2. **不带倾向**。待决策事项只列出选项，不暗示推荐。
3. **不臆想数据**。没见过的文件名、路径、数据口径一律不编造。
4. **保持精炼**。每个条目控制在一句话。这是交接文档，不是周报。
5. **不自行推送 GitHub**。只在用户明确说「推送」「push」「推到 GitHub」「推git」时才执行 git push。
6. **更新时间取系统时间，绝不推断**。执行 `date "+%Y-%m-%d %H:%M:%S"` 获取。
7. **每次会话结束前检查并更新**。有产出就必须更新 progress.md。
8. **内容修剪是义务，不是可选项**。过期的决策、已废弃的模块必须清理。
9. **编号不得重复**。§4 编号各自连续，删除后逐项前移。
10. **所有进度条目必须挂工作流标签**。格式 `[工作流] [平台/模块]`。新建条目未打标签 = 不合格。
11. **已完成列表膨胀时主动提示压缩**。超过约 30 条或明显过长时询问用户，压缩由用户口头确认后执行，不可自动。

---

## 触发时机

- 用户主动说"更新 progress" / "更新交接文档" / "同步进度"
- 每完成一个阶段性产出后，**主动询问**用户是否更新
- 会话结束前，**主动检查**是否有未记录的产出
- 不要每句对话后都更新

---

## 输出格式

更新完成后简洁告知：
```
progress.md 已更新：
- [模块名]：变化内容简述
- [模块名]：变化内容简述
是否需要同步到 tdrive？
```
