# 1、需求总述
## 1.1 需求背景
启航平台是中华财险新一代核心系统的员工视角系统门户，承担「应用的发现与访问」入口职能。当前应用信息分散、更新动态与操作指引缺乏统一承载，员工查找系统、了解变更、获取操作指引的成本较高；同时 PMS（项目管理系统）的发布计划与应用侧的更新动态彼此割裂，发布信息无法自动回流到员工视角的门户。

本期重点打通 **PMS 与启航的双向关联**，以「应用」为中枢，把更新日志、操作手册、应用地图整合到统一的员工门户中，形成「启航—知行—聆听」深化应用工具的雏形。

## 1.2 编写目的
明确本期启航平台在应用管理、更新日志、操作手册、新一代应用地图四个模块的功能范围、业务规则、交互要求与验收标准，作为设计、研发、测试与上线验收的统一依据。

## 1.3 名词释义
| 本需求涉及到的常用名词 | 名词解释 | 边界说明 |
| --- | --- | --- |
| 启航平台 | 中华财险新一代核心系统员工视角系统门户，负责应用的发现、访问与信息聚合 | 本期聚焦员工视角门户侧能力 |

### 3.1.1 应用分类管理，支持二级分类
应用分类管理从当前单层结构升级为两层结构

<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/159868/1785407393978-7e36d115-2ad1-480a-9b2b-daee37d81424.png)

#### 3.1.1.1 创建一级分类
当用户在分类管理页点击"新增一级分类"时，系统应弹出一级分类创建表单（分类名称必填），创建后该分类出现在列表顶层

#### 3.1.1.2 新增子分类
+ 当用户在某一级分类行点击"新增子分类"时，基于该父级创建子分类，并自动建立父子归属关系
+ 若用户提交的分类名称为空或与同级已有分类重名，则系统应拦截提交并提示"分类名称不可为空/不可重复"
+ 当某一级分类下存在子分类时，系统应在列表中以层级缩进/可折叠方式展示其子分类，并随父级展开或收起

#### 3.1.1.3 分类顺序调整
+ 子分类同样支持鼠标拖动改变顺序，子分类的顺序仅可在当前父分类内部进行调整
+ 调整父分类顺序时，连带内部子分类一起进行调整

#### 3.1.1.4 删除分类
+ 可以删除父分类和子分类
+ 若删除的一级分类下存在子分类或已挂载应用，则系统应禁止删除并提示"请先迁移或解绑下属子分类与应用"
+ 若删除的二级分类下已挂载应用，则系统应禁止删除并提示"请先迁移或解绑下属应用"

+ 用户将 Switch 从 `不公开` 拨为 `公开` 时，在应用详情页展示该文档。
+ 用户粘贴格式文本时，自动识别并转换为富文本 HTML。
+ 用户未保存就离开工作台页面时，提示"有未保存的更改，确定离开吗？"

### 3.4.5 对外展示
**应用详情页「操作手册」Tab：**

+ 展示该应用已发布的操作手册目录树（左侧）和文档内容（右侧）
+ 若该应用无已发布的操作手册，展示"暂无操作手册"空态
+ 目录下无可见文档时，隐藏整个目录

**对外查询接口：**

+ 提供查询接口供 PMS、应用内等场景拉取操作手册
+ 入参至少包含：应用标识
+ 接口返回目录树结构 + 各文档内容
